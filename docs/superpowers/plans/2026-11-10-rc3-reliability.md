# RC3 解析与同步可靠性交付

用户已授权本轮修复后直接交付，不新增功能范围，不操作正在使用的程序或清空数据。

## 设计与验收

1. AI 使用明确的事件 JSON 合同（行动、日期、24 小时时刻、结束、分字段原文证据），兼容原引用合同。缺失值为 null；本机校验字段与原文，不接受模型编造的日程。已保存事件和人工决定优先。
2. 输出预算适配推理模型，遇到真实截断最多一次有界恢复；完整可验证 JSON 可用，残缺 JSON 不落库。认证/费用/超时不无限重试，保留隐私与停止屏障。
3. 时段按每个时刻局部作用域转换：晚上/傍晚/晚间/下午与 PM，上午/凌晨与 AM；支持跨时段区间，不将一处“下午”套用整封邮件，保留含糊日期审核。
4. IMAP 区分根单文本与多部分邮件，仅 PEEK 正文、不下载附件。合法 NIL/空/quoted 正文不当作网络失败；损坏或声明截断保持游标，不静默跳过。删除竞态经确认后才略过已不存在 UID。
5. 测试连接明确只验证认证/只读打开；读取失败展示真实阶段和重试安排，不误导更换授权码，不抹除未解决的读取错误。
6. 先写复现回归，运行完整测试及最终独立窗口；源码、安装包、ZIP、校验清单、数据延续入口与变更日志按 RC3 单独保存。真实服务结果与模拟结果分别记录。

## 执行顺序

- 检查协议与时间根因 → 失败回归 → 最小修复 → 相关回归。
- 全量后端/前端、冻结依赖、构建检查 → 新目录构建 → 实际窗口的晚间 JSON 预填、截断恢复及退出验证。
- 保存版本与产物，保留 RC1/RC2 运行文件与用户原数据，不自动退出或切换用户实例。
