## 审核结论与修正决策

1. **版本信息失配**：health API 仍写 0.2.0。新增构建时版本一致性检查，健康/诊断/备份/前端/安装器/UA 同一版本；修订不能改写 v0.2.2 原包。
2. **AI 依赖/规则阻塞**：当前解析 worker 会持 activity 遍历。AI 单独有界 worker，规则先提交后返回，不让 30 秒请求阻断新邮件/提醒；请求快照包含 db.generation、邮件版本和设置版本，回写逐项复查。规则足够完整不出站，主动重解析才可重新请求；已接受/忽略不重建。
3. **AI 隐私与合同缺失**：发送主题和必要片段，屏蔽邮箱、手机号、URL token/个人称呼；URL只保留域名，密钥不进 profile/API命令回执/日志/备份。输出引用脱敏输入中的精确证据，先映射回本机再用原解析器确认时间；AI不得直接写UTC、编造公司或执行工具。新增建议只进入审核，可靠规则仍可自动形成事件。保留解析来源和错误码。启用前说明外部传输和潜在费用。
4. **网络目标与限流**：AI允许 HTTPS 用户配置端点，兼容本机模型仅允许显式 localhost/127.0.0.1 HTTP；公网 HTTP、userinfo、fragment 拒绝。Webhook 只允许 HTTPS，拒绝本机/私网/链路本地/元数据地址与重定向；校验证书、限制响应字节、超时、一次请求不内层重试。生产请求不继承代理环境。测试以注入 transport/本机虚构接收器执行，不能据此声称真实服务成功。
5. **多通道投递不能共享一个结果**：每个 reminder 已有 channel，但当前只有 Windows。Windows 与 webhook 各自独立 reminder/attempt/idempotency_key；一个成功不得掩盖另一个失败。关闭/换目的地抑制未发送计划，已出站超时标 unknown，不重复追发；启用时只创建尚未来临计划，不补发历史模板。关机仍不发送。
6. **申请仅有 CRUD**：阶段历史/关联/拆分需要原子事务与双方版本。复用审计表保存显式 old/new/任务ID历史；不因同公司自动合并，不自动关掉任务。关联变动保持任务ID和提醒计划，不为关联重建提醒；关闭申请的任务取消是另一个用户显式选择。
7. **准备事项与事件互相影响**：准备项独立于企业日程。子项支持模板、增删改/勾选；若用户设置提醒，创建并关联独立 custom Task，父改期/取消不自动删除或移动人工计划，UI展示影响。无日期不设定时提醒；重复模板幂等，历史/JSON/备份保留关联。
8. **schema/旧备份**：新表必须新迁移，冻结 0001–0004 不改。旧schema纳入显式支持集合，隔离迁移/恶意schema拒绝/回滚测试；新增关联FK、count、导出白名单与全部清理一起更新。新 settings secrets 仅存 vault 引用且可下载副本必须清引用/停AI停webhook并VACUUM，恢复不自动联网。内部回滚保持引用与业务一致。
9. **ICS 导出不等于双向同步**：精确面试为 VEVENT，截止/准备为 VTODO；日期-only保留 VALUE=DATE，未知日期排除并显示计数。不假设结束，稳定 task UUID作为UID，版本作为SEQUENCE，UTC/CRLF/UTF-8 75字节折行；取消仍导出 CANCELLED、完成VTODO=COMPLETED。仅快照导出，不保证重复导入时各家日历自动替换/撤回，帮助必须说明。来源/会议链接默认不导出，需用户明确选择。第三方解析器往返验收。
10. **多邮箱服务器差异**：provider固定QQ/foxmail、163、126；NetEase用IMAP ID扩展识别客户端再只读INBOX，凭据逐账户、边界独立。移除后重连复用原记录而不撞唯一地址；跨账户同MIME保留审核关系，不自动合并。
11. **发布门槛不能自相矛盾**：0.3.0/0.4.0 为功能阶段，1.0.0-rc.1为功能完整候选；只有全部准入证据真实完成才标1.0.0。缺少真实服务/7天/5人/干净Windows不停止可独立完成的开发，但最终不得宣称正式发布。外部验收单单独记录，不把模拟样本冒充许可真实样本。

## 实施顺序与权衡

维持用户已确认的 A→B→C→D→E→F→G。增加 S0（版本/隐私/备份公共边界）在 A 前；每包完成必须打通前后端、回归与审查，跨包最终集成测试。A不依赖看板，AI建议只写候选；B在用户确认时才建立申请关系。因此避免先引入未实现看板接口。C扩展真实Reminder渠道，不用同一发送器顺序发送两次。E需schema并映射独立custom任务，F消费现有任务数据无需另外复制日程。
