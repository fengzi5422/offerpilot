# M13 导出、备份恢复与数据生命周期详细设计

状态：待确认｜范围：P0｜需求：F10、NFR-09、隐私控制

## 1. 职责和文件格式

拟建 `services/{exports,backup,restore,privacy}.py`、`persistence/backup.py`。导出用于阅读/迁移，备份用于恢复整个应用数据，两者 UI 明确区分。

| 类型 | 内容 | 使用方式 |
| --- | --- | --- |
| CSV | 任务或申请，UTF-8 BOM，稳定列名 | 表格查看，不直接恢复应用 |
| JSON | schema_version、导出时间、任务/申请及关系 | 结构化数据导出，P0 不承诺任意 JSON 导入 |
| 备份 ZIP | manifest.json、data.sqlite、可选 evidence.json | 受控完整恢复 |

CSV 列：id、company、position、title、kind、status、priority、due_at_utc、due_date、starts_at_utc、timezone、precision、created_at_utc；没有的值为空。以 =、+、-、@、TAB、CR 开头的文本单元格做公式注入转义；JSON 保留原始文本值。

manifest：format_version=1、app_version、schema_revision、created_at、files[{name,size,sha256}]、record_counts、contains_evidence、credentials_included=false。哈希用于损坏检测，不宣称能证明备份来源可信。

## 2. 导出和备份流程

用户选择类型，服务生成 job 和内部 UUID 文件名；完成后返回限时 24 小时的认证下载 ID，浏览器选择保存位置。API 不接受任意磁盘路径。

使用 SQLite backup API 生成一致快照，不能复制正在运行的 WAL 主文件。快照创建后单独清除 credential_ref、临时会话、命令缓存、敏感临时正文与运行 lease；账户状态转 auth_required，AI/外部通知 disabled。导出包不含实际系统凭据。依据：[SQLite Backup API](https://www.sqlite.org/backup.html)。

上述清理用于可下载的用户备份。升级/恢复前的内部回滚快照保留原库业务状态与凭据引用，以便同机完整回滚，仍不包含系统凭据本体；它只留在当前用户受限备份目录，不通过普通下载端点直接暴露。若用户要导出内部快照，必须先走相同脱敏打包流程。

默认备份保留任务、事件最小证据和来源元数据，不含原始 MIME/临时全文/附件。用户可选更完整证据，界面标明可能包含个人信息。导出备份本身默认不加密，下载前说明其私密性；不能把“无凭据”表述为“没有敏感信息”。

快照脱敏后必须在副本上执行重建/VACUUM，清除被剔除数据在空闲页的残留，再校验并打包；不对活动数据库执行这一步。临时 cache 不打入包，source_cache_ref 清空。

## 3. 两阶段恢复

**校验阶段不改变当前数据：** 上传到隔离目录；检查尺寸、路径、文件白名单、哈希、schema 版本；以受限只读连接检查 SQLite 完整性与外键，拒绝意外触发器/视图/扩展和未知表结构；不执行来自包中的 SQL 脚本。备份 schema 新于当前应用则要求升级；旧 schema 在临时副本迁移后再校验。

**确认阶段：** 展示将替换的数据数量、备份时间、需要重新授权的账户；用户确认后暂停 Worker/写 API，等待在途操作结束，使用 backup API 保存当前库为恢复点，关闭数据库连接。在同卷 staging 中准备新库，检查后原子替换；WAL/SHM 仅在连接全关闭并确认目录后处理，不将旧 WAL 应用到新库。

恢复启动时清理所有 lease；未完成发送标 unknown；按新的当前时间计算漏提醒，不追发历史模板。重新生成 profile 运行会话和本机实例身份，清除全部凭据引用；本地任务可立即使用，邮箱与外部服务必须重新授权。

替换失败恢复旧库；迁移失败停留恢复界面，保留两个备份与诊断。恢复不合并两套数据，避免重复任务；如需合并，后续另设冲突导入功能。

## 4. 保留、清理和账户删除

| 操作 | 默认影响 |
| --- | --- |
| 暂停监听 | 仅停止新同步，任务和提醒继续 |
| 移除邮箱 | 停止同步/删除凭据；任务保留、来源标已断开 |
| 清邮件缓存 | 清正文缓存/链接；保留任务和用户选定最小证据 |
| 删除来源证据 | 清证据文本与敏感来源字段；任务标 source_unavailable |
| 删除全部个人数据 | 明确确认后清业务库、缓存、应用管理的备份、凭据；重启向导 |

自动备份保留最近 5 份，手动备份不自动删；日志按 M14。清理前 preview 返回数量/范围及短期 token。删除数据时告知用户下载到其他目录的导出文件仍需自行删除。SQLite 普通删除不承诺磁盘取证级擦除；可在维护期 VACUUM 减少残留，但不提供虚假安全保证。

## 5. 验收

有活动 WAL 时备份恢复仍包含已提交任务；损坏、路径穿越、超量解压、未来 schema 均在替换前拒绝。恢复失败可回到原数据；恢复后不使用旧凭据自动联网。导出中注入测试 secret 不出现；CSV 恶意公式作为文本。删除邮箱不丢手动任务，删除全数据不会越出应用目录。
