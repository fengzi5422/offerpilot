# M01 运行时与生命周期详细设计

状态：待确认｜范围：P0｜需求：A6/A9、NFR-01/02/03/05

## 1. 职责与边界

负责单实例、数据目录、API 和 Worker 生命周期、托盘、关闭与恢复。业务操作委托用例服务，不在托盘回调中直接操作数据库。一个进程，不启动多个 Uvicorn worker；生产不启用 reload。

拟建文件：`backend/app/runtime/{bootstrap,lifecycle,single_instance,tray,recovery}.py`、`backend/app/main.py`。每个文件分别承担启动装配、状态管理、互斥、托盘适配和恢复检测。

## 2. 启动协议

1. 计算当前用户数据目录，检查写权限与剩余空间；开发使用项目 `.runtime/dev`，测试使用临时目录。
2. 获取当前用户命名互斥锁。第二实例向当前用户 ACL 限制的命名管道发送 `open_ui`；锁仍有效而管道异常时提示重试，不启动第二组 Worker。
3. 初始化脱敏日志和 run_id；校验 SQLite、执行升级前备份/迁移。
4. 绑定 `127.0.0.1` 的操作系统分配端口，生成本次启动会话引导码；将端口与 PID 写入仅当前用户可访问的运行信息文件，不写引导码。
5. API ready 后启动规则处理、提醒和邮件 Worker；初始化托盘。只有数据库 ready 才允许对外报告 ready。
6. 手动启动打开向导/今日待办；开机自启只显示托盘。UI 初始化失败时托盘提供重开界面与诊断入口。

`Lifecycle.start(mode: interactive|autostart) → RuntimeInfo{run_id, port, state}`；`stop(reason) → ShutdownResult`；`pause_sync()` 只暂停邮箱，不停止已有任务提醒。

## 3. 并发和任务调度

| 执行链 | 默认行为 | 隔离方式 |
| --- | --- | --- |
| API | 异步 HTTP；阻塞存储用受控线程执行 | 每个用例独立 Session |
| Mail Worker | 默认每 180 秒；单账户一次同步 | IMAP 独立线程，超时 30 秒 |
| Parse Worker | 每 2 秒取最多 20 条；规则串行 | 不占用通知执行线程 |
| AI Worker，P1 | 并发 1，单请求 30 秒 | 有界队列，失败不阻塞规则 |
| Reminder Worker | 每 15 秒取最多 50 条 | 独立调度链与任务互斥 |
| 托盘 | 主线程消息循环 | 线程安全命令队列转入服务 |

所有循环都有停止信号和顶层异常保护。单轮失败记录结构化错误并退避，不能令 API 或其他 Worker 一并退出。阻塞调用必须有自身 timeout，不能只取消外层 await。

## 4. 状态与退出

状态：`starting → ready → stopping → stopped`；启动失败进入 `recovery_required`。邮箱或通知异常属于模块 degraded，不能把整个应用标为不可用。

关闭浏览器不改变进程状态。托盘退出显示提醒停止说明；确认后停止接新任务，等待当前数据库事务完成，通知网络调用最多等待 10 秒，写入退出标记，关闭连接/托盘，释放互斥。未结束的发送由下一次启动按 unknown 处理，不能假定失败。

## 5. 恢复与时间

运行心跳每 30 秒保存一次；比较墙钟与单调时钟的差异，检测超过 90 秒的挂起/时钟跳变。恢复时先标记迟到提醒并汇总，再发起一次同步；不按遗漏轮询次数重复执行。所有时间判断使用可注入 Clock，后台周期用单调时钟。

重启后：过期 parse lease 重新领取；sync job 置 interrupted 并从游标续扫；通知 attempt 已开始但无结果的记录置 delivery_unknown。不存在发送尝试的已领取提醒可安全归还 pending。

## 6. 失败与验收

- 数据库迁移失败：保持恢复界面，所有业务 Worker 不启动，提供备份路径及错误编号。
- 凭据库失败：允许本地任务读写，邮箱/AI 标为不可用；不回退明文存储。
- 两次双击只能有一组 Worker，第二次打开同一实例页面。
- 关闭浏览器后测试提醒仍可触发；显式退出后无后台进程残留。
- 模拟暂停 2 天后仅有一次恢复汇总，同步从已提交位置继续。
- IMAP 超时不影响任务编辑；异常退出后无半条任务/提醒事务。
