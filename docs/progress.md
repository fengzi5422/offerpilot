# OfferPilot 当前进度

更新日期：2026-11-10（北京时间）。范围：已批准的 P0；当前交付等级为本机开发原型，尚不宣称达到可发布 MVP。

## 产品逻辑与开发边界

目标是把招聘邮件变成可核对的行动，减少错过截止与笔面试的风险。核心链路为：只读获取/导入邮件 → 规范化及传输去重 → 规则分类/时间提取 → 明确动作生成任务，有歧义进入审核 → 数据库持久化提醒 → 发送结果与恢复汇总。

邮件、动作候选与任务分开保存；重复导入/同步不重复建任务，人工修改不被重新解析覆盖。日期与精确时刻分开，收信后 48 小时等相对期限保留参照候选并要求确认。改期/取消在 P0 拦截送审，由用户处理原任务，P1 才提供自动关联向导。AI、自动求职看板、日历与移动通知仍属于后续范围。

需求依据依次为原始 PRD、技术概要、详细设计和已批准的实施计划；历史草案的“待确认”不再代表 P0 未获批准。2026-11-09 的开发批准保存在 `superpowers/plans/2026-11-09-p0.md`。

## 本轮继续完成的工作

- 补齐运行中每 24 小时一次的脱敏自动备份，保留五份，写入失败保留旧备份，重启不重复执行。
- 补齐可编辑提醒模板、安静时段与已有任务的事务性重排；只修改标题不会重置已经延后的提醒。
- 修复无效设置先修改 Windows 开机启动项的问题，数据库失败时补偿外部设置。
- 请求流按实际大小限制，登录引导也校验同源与内容类型，避免超量请求进入解析器。
- 默认系统通知隐藏任务名称，保留应用内详情；通知身份与安装快捷方式保持一致。
- 审核保留原始时间文字和相对期限参照；日期型任务按日期归组；任务来源可读并展示真实域名。
- QQ 网络失败持久化递增退避与抖动，重启延续计数；认证失败暂停自动尝试，连接测试可恢复状态。
- 邮箱首次测试失败仍可继续重试；移除凭据失败保留重试入口；重新添加已移除邮箱不会执行旧连接的排队任务。
- 升级前快照、试迁移与完整性校验，实际升级失败恢复原库；拒绝未知或更高版本数据库。
