# OfferPilot 本机使用指南

本指南对应已加入多邮箱、AI 辅助解析、申请看板、外部提醒、准备事项和 ICS 导出的本机版本。具体版本请查看「设置与诊断」及交付包中的版本清单。功能可用与真实环境验收是两件事；尚未完成的验收范围见本文末尾。

## 1. 安装、启动与数据目录

安装版从桌面或开始菜单启动。便携版请先完整解压，再运行目录中的 `OfferPilot.exe`。**保留整个便携目录及其子目录**，仅复制 EXE 会导致界面或运行组件缺失。程序使用独立桌面窗口；缺少 Microsoft Edge WebView2 Runtime 时，按启动提示安装微软官方运行组件。

当前交付可能没有代码签名，Windows 可能显示来源或信誉提示。先确认安装包来自你信任的交付来源，核对归档中的文件名与 SHA256，再按 Windows 提示决定是否运行。可以在文件所在目录的 PowerShell 中核对：

```powershell
Get-FileHash .\OfferPilot-Setup.exe -Algorithm SHA256
```

程序默认将数据写入 `%LOCALAPPDATA%\OfferPilot`。在文件资源管理器地址栏输入这一地址即可打开。程序文件与个人数据分开保存；重新安装程序不等于恢复或删除个人数据。

如果需要使用独立目录，可在**完整便携程序目录**打开 PowerShell，明确指定：

```powershell
.\OfferPilot.exe --data-dir "D:\OfferPilot-Data\personal"
```

也支持 `OFFERPILOT_DATA_DIR` 环境变量，启动参数优先。使用独立目录后，每次都通过相同参数或相同快捷方式启动。普通快捷方式仍可能打开默认目录。默认目录、你指定的目录和开发检查目录是不同的数据集，不会自动合并；发现“任务不见了”时先确认本次打开的是哪个目录，不要急于导入重复数据。

## 2. 关闭窗口、退出与重启

- 普通运行时，点击窗口关闭按钮会隐藏到 Windows 托盘，后台同步与提醒继续工作。可在托盘菜单选择「打开界面」。
- 在托盘选择「退出」才会停止程序。退出、关机或电脑休眠期间，应用无法发送 Windows 通知或 webhook，也不能同步邮箱。
- 保存成功的任务、申请阶段、准备事项、设置和提醒计划写入当前数据目录，正常退出或重启不会清空。重新打开同一目录后继续读取。
- 重启后的迟到提醒会按原计划与有效期处理，可能显示错过提醒汇总；不要把它当作关机期间已经发送。结果未知的外部投递不会自动重复追发。

「设置与诊断 → 提醒与运行」可以启用登录 Windows 后自动运行。它依赖用户登录与程序成功启动，不能提供关机后的云端提醒。修改设置后，应在实际设备上测试系统横幅；Windows 勿扰和通知权限可能影响显示。

## 3. 连接 QQ、Foxmail、163 与 126 邮箱

首次引导可以跳过邮箱，先创建待办或导入 `.eml`。稍后进入「设置与诊断 → 邮箱连接」：

1. 选择邮箱服务，填写与之对应的完整邮箱地址。
2. 到邮箱厂商的网页设置中开启 IMAP，获取**客户端授权码**。
3. 将授权码填入应用，选择首次查看范围：最近 14 天、最近 30 天或从现在开始。
4. 点击「安全保存并测试连接」。测试成功后，可在该账户旁点击「立即同步」。添加其他邮箱时点击「连接另一个邮箱」。

| 邮箱地址 | 选择的服务 | 授权码入口提示 |
| --- | --- | --- |
| `名称@qq.com`、`名称@foxmail.com` | QQ / Foxmail | QQ 邮箱网页版「设置 → 账户」，开启 IMAP 并获取授权码 |
| `名称@163.com` | 网易 163 | 163 邮箱网页版「设置 → POP3/SMTP/IMAP」，开启对应服务并完成客户端授权 |
| `名称@126.com` | 网易 126 | 126 邮箱网页版「设置 → POP3/SMTP/IMAP」，开启对应服务并完成客户端授权 |

厂商可能调整菜单或要求安全验证，以其网页指引为准。这里填写授权码，不是邮箱登录密码。授权码保存在 Windows 凭据管理器，不会在界面中回显。

应用固定使用厂商的 TLS IMAP 服务器，只读打开收件箱并读取必要正文；不发送、删除、归档邮件，也不主动修改邮件已读状态。网易连接会发送不含授权码和邮箱地址的客户端身份信息，以满足其 IMAP 要求。

每个账户分别保存凭据、同步进度和状态，可以独立暂停、恢复或移除。移除账户会停止连接并删除其授权码，已有任务仍保留；以后重新添加同一地址会复用原账户身份，不会因此重建旧任务。相同邮件出现在不同账户时，重复候选可能进入审核，请核对后处理。

认证失败时先检查 IMAP 是否开启、授权码是否撤销或填错；在账户的「更新授权码或移除账户」中换码。网络或证书失败时检查联网状态后重试。不要为连通性关闭证书校验。

## 4. 从邮件到任务，再到申请看板

在收件列表打开邮件，核对行动、日期、时刻及来源依据。规则能够完整确认的事项可以形成任务；模糊日期、多日期、改期、取消和 AI 建议需要审核。省略年份时使用「设置」里的默认年份，请按实际招聘季更新；只有日期不等于已经确定提醒时刻。

改期或取消邮件应关联到原事件，避免再建一条独立事件。任务中的人工修改与已作出的接受、忽略决定会保留。任务页可以新建、编辑、完成、取消或重新打开任务；已确认的精确时刻才用于定时提醒。

「申请看板」可以手动新建公司和岗位，在已投递、测评、笔试、面试、等结果、录用通知、已关闭之间调整阶段，并查看历史。相同公司不同岗位请分别记录。关联或拆分任务不会自动移动其时间；关闭申请也不会自动取消已有任务和提醒，需要时在任务页另行处理。

## 5. 可选 AI 辅助解析

AI 默认关闭，本地规则不需要模型密钥。正常识别中，规则已经充分处理的邮件不会因此调用外部 AI；明确点击「AI 辅助识别」则是一次主动请求。邮箱同步本身仍会连接你配置的邮箱服务。

需要 AI 时，在「设置与诊断 → AI 辅助解析」操作：

1. 填写 OpenAI 兼容 API 的**基础地址**，通常以 `/v1` 结尾，不要再附加 `/chat/completions`，也不要把密钥放入地址。
2. 填写服务商提供的模型名称和 API Key。公网服务要求 HTTPS；你明确配置的本机模型可以使用 `http://localhost:端口/v1` 或 `http://127.0.0.1:端口/v1`。
3. 阅读并勾选发送范围与费用说明，选择启用后点击「保存并启用」。更换地址或模型后需重新确认；每次保存启用配置都要主动勾选。
4. 可点击「发送固定示例测试」。它联系已保存的服务，使用虚构主题与正文，不发送你的真实邮件，也可能产生少量服务费用。

实际辅助解析会发送必要的邮件主题与正文片段：主题最多 500 个字符，正文输入最多 12000 个字符，再尽量隐藏邮箱、手机号、个人称呼，将链接缩减为域名。**这不是完全匿名化**：剩余内容仍可能识别个人、公司或招聘事项。费用、服务可用性与接收方的数据处理规则由所选服务决定，请先自行了解。

Key 安全保存在 Windows 凭据管理器，保存后不回显；留空保留原 Key。AI 结果进入审核，不会代你投递、改约或执行邮件指令。认证、额度、限流、网络或返回内容异常时，规则结果继续保留。可随时点击「立即停用 AI」；删除配置会同时移除已保存密钥。停用或删除不能撤回已经发给服务的内容。

## 6. 外部提醒：通用 webhook

Webhook 默认关闭，与 Windows 通知分别安排和记录结果。它需要一个接受通用 HTTPS JSON POST 的公网接收器。常见手机推送服务未必接受此格式；不兼容时需要你自己部署或选择一个可信中转服务（relay）转换格式，应用不会自动替你创建中转或手机账号。

在「设置与诊断 → 外部提醒 · Webhook」填写完整接收地址和可选 Bearer 令牌，阅读说明并勾选同意，然后保存启用。地址可以包含接收服务的专属路径或查询凭据，因此完整地址和令牌都进入 Windows 凭据管理器，保存后只显示服务来源，不回显完整内容。

接收器需要读取以下 JSON 字段，并按 `idempotency_key` 去重：

```json
{
  "app": "OfferPilot",
  "message": "你有一项求职待办，请打开OfferPilot查看",
  "idempotency_key": "每条提醒的稳定防重复标识"
}
```

如果填写令牌，请求还会携带 `Authorization: Bearer <令牌>`。不发送真实任务标题、原邮件、邮箱地址或任务链接。更换接收地址时，原 Bearer 令牌不会自动沿用；请填写新接收器需要的令牌，留空表示新地址不使用 Bearer 认证。未改地址时，令牌留空保留原配置，也可勾选清除令牌。

保存启用后可以发送固定内容测试，再到接收服务和手机端核对。结果的含义是：

| 结果 | 应如何处理 |
| --- | --- |
| 接收服务已受理（HTTP 2xx） | 只证明接收器受理，不证明手机已显示或已读；去接收服务核对转发结果 |
| 认证或请求被拒绝（如 400、401） | 本次不自动重试，检查格式、地址与令牌 |
| 限流或服务失败（429、5xx） | 定时提醒在有效期内有限重试，最多尝试发送三次（含首次）；固定内容测试不会自动重发 |
| 发送结果未知（unknown） | 接收方可能已受理，应用不会自动重发；先核对接收记录，避免重复通知 |

应用拒绝本机、私网和元数据网络目标，不跟随跳转，不会降低 TLS 校验要求。停用或更换目的地会处理未发送的外部计划，已经发出的请求无法撤回。启用时只安排仍在将来的提醒，不补发历史提醒；退出、休眠和关机期间无法发送。

## 7. 准备事项与独立提醒

打开已保存任务或事件的详情，在「准备事项」中点击「添加准备模板」，或填写自己的准备内容。模板按事项类型提供建议，可以改写、勾选完成或删除；重复添加同一模板不会反复建立同一项。

清单操作**即时保存**，不是等到事件表单整体保存才生效。新增或编辑时，可以选择一个明确的未来提醒时刻；输入框使用当前设备时区。未选择时刻的准备项只是一条清单，不会凭空推算日期或设定时提醒。

设置提醒后，应用创建一条关联的独立准备任务，可以在任务页修改。父事件改期或取消时，准备清单和已设定的独立提醒继续保留，详情会提示影响；请自行核对新的安排，需要调整时在准备事项或关联任务中修改。勾选完成或删除准备项也会处理其关联提醒。

## 8. 导出到其他日历（ICS）

在「设置与诊断 → 数据导出与备份 → 导出到其他日历（ICS）」下载文件；日历页也提供导出入口。默认导出标题、日期与时间，不附加地点、会议链接、备注等细节。确需这些内容时，主动勾选包含细节，并把导出文件当作个人资料保存。

ICS 是**当前安排的一次快照，不是双向同步**。面试、笔试导出为日程，截止或准备任务导出为待办；只有日期的事项保留日期型，时间未知或尚待确认的事项可能被跳过，下载提示会给出数量。未提供结束时间的日程不会擅自补时长。

应用保留稳定标识和版本，但不同日历软件对待办、取消状态、更新和重复导入的处理不同。有的软件会新建重复事项，有的软件不显示待办；重新导入不保证替换旧事项。OfferPilot 中的改期、完成或取消也不会自动改变已导入的日历，请在目标软件中核对并清理旧版本。

## 9. 备份、恢复、升级与回退

在「设置与诊断」点击「下载备份」，把 ZIP 放到私密位置。默认下载备份不含邮箱授权码、AI Key、完整 webhook 地址与令牌，也不包含邮件正文片段和来源证据；仍保留任务、申请、准备事项和必要的邮件元信息。**手动备注、标题、准备文字等仍可能含个人信息，不能把备份当作匿名文件分享。**

程序运行期间约每 24 小时保存一份日常自动 ZIP，在当前数据目录的 `backups` 中保留最近五份；手动下载、升级前和恢复前的恢复点分别保留。程序未运行时不会自动备份。

恢复步骤：

1. 先为当前数据下载一份备份，确认现在使用的目录。
2. 点击「选择备份并校验」，查看校验结果，再点击确认恢复。恢复会替换当前数据，不是把两个数据集合并。
3. 按页面提示从托盘重新打开界面。邮箱需要重新授权；AI 与 webhook 恢复为停用且不带密钥或接收凭据，需要重新设置、确认同意后才能联网。自动运行设置也需重新确认。

本轮数据结构包含 `0005_preparations`。旧结构升级前，程序先在 `backups/pre-upgrade-*.sqlite` 留下本机快照，并在隔离副本中试迁移，再升级当前数据库。恢复前也会生成 `pre-restore-*.sqlite`。这些内部恢复点可能包含更完整的个人来源和凭据引用，请保护整个目录，不要直接分享，也不要把 SQLite 快照当成界面要求的 ZIP 导入。

升级前，建议同时保留完整旧程序目录及用旧版导出的备份。需要回退时：先退出程序，保留当前数据不动；找出**与旧程序支持结构匹配的旧备份**，在单独的数据目录启动完整旧程序，再按该版本的恢复功能恢复。**不要仅换回旧 EXE 就让它直接打开升级后的数据库**。仅有内部 SQLite 快照时，应按对应版本的恢复步骤处理或获得协助；不要自行覆盖仍运行中的数据库。

## 10. 清理来源与导出诊断

「设置与诊断 → 隐私与本地数据清理」提供清除邮件缓存、删除来源证据和删除全部本机数据。先看影响范围再确认。清除来源不会自动删掉你手动写入的任务备注、标题、申请信息或准备内容；若要移除其中的个人信息，需要分别编辑或删除。

清理影响当前数据，不会替你删除已经下载到其他位置的 `.eml`、CSV、JSON、ICS、备份 ZIP，也不会清除接收服务或模型服务已经收到的内容。旧备份和内部恢复点可能保留清理前的信息，应另行检查和删除。原邮箱中的邮件不受这些清理操作影响。

诊断包在「运行诊断 → 导出诊断包」生成，仅下载到本机，不自动上传。它包含版本、模块状态、数量统计和白名单运行日志，不包含业务数据库、正文、邮箱地址或凭据；分享前仍请自行检查。

## 11. 当前验收范围

自动化测试与虚构示例可以验证流程和错误处理，不能代替你自己的邮箱、模型服务、手机接收器或目标日历的验证。真实 QQ/163/126 邮箱连通与长期同步、真实 AI 服务、手机可见通知、连续七天稳定性、至少五位独立用户试用及干净 Windows 系统安装等，应以交付验收记录中的实际证据为准。没有证据的项目继续保留待验，不因界面出现按钮或测试样例通过就视为完成。

数据与外部传输的详细说明见[隐私与数据说明](privacy.md)。
