## 问题与结果

用户安装后打开根地址即出现 NOT_FOUND。已根据对应请求日志、端口及运行路径确认：默认数据目录仍由另一便携目录的旧实例占用；该目录缺少 `_internal/frontend/dist`，API 正常而页面 404。新安装目录资源完整，但旧单实例协议会让旧实例继续打开浏览器。

新版在启动服务前验证 index.html 与引用文件；缺失时显示中文修复提示。第二次启动先核对桌面协议，旧版占用时提示用户先从旧版托盘退出，不强制关闭、不再命令旧版打开浏览器。安装器关闭自动结束应用行为。

主界面由 pywebview 6.2.1 + Windows WebView2 承载，独立可缩放窗口，不启动浏览器作为主界面。关闭窗口触发隐藏至托盘；托盘打开/再次启动唤起，正常会话保留当前编辑。备份恢复、全部清理或过期造成会话失效时重新生成启动码，并改变无敏感内容的 launch 查询参数，使界面完整加载并认证。外部会议链接由系统打开。

## 实际 WebView2 与安装文件验收

`scripts/smoke_desktop.py` 只向自建子进程传入临时调试端口，不连接用户浏览器，普通程序不开调试端口。数据均为项目 `.runtime` 内虚构样本。

最终冻结文件使用安装配方的隔离副本安装到 `.runtime/desktop-install-validation/program`；副本仅改变安装标识、路径、输出名，并禁用快捷方式、自动运行和卸载登记，避免改写用户已有安装。文件复制成功，安装后 EXE 与最终便携 EXE SHA256 完全一致，界面资源存在。正式安装包本身编译通过；未用它覆盖用户真实安装。

安装后的真实独立窗口（`.runtime/desktop-installed-ui-final`）通过：

1. WebView2 渲染、启动认证、跳过引导，主界面成功出现。
2. 通过界面文件输入的 change 流程导入虚构 .eml，提取 2050-01-02、15:00–16:00、上海市示例路100号及会议链接。
3. 从已处理邮件打开事件，日期与时间实际输入值正确；改为 15:30 保存，跳转日历显示 15:30–16:00。
4. 有效会话再次启动保持原页面；真实备份/恢复撤销会话后，再次启动完成重新认证。
5. 720×540 内容视口无水平溢出，截图已检查；此为 WebView2 视口模拟，不等同原生窗口尺寸或 DPI 人工验收。
6. IPC close_ui 调用原生 WinForms Close，与标题栏同一 closing 事件；处理器状态变为隐藏、服务继续，第二次启动恢复可见状态；退出后日志 app.stop。可见状态来自控制器，未单独用桌面工具验证 Win32 置前/隐藏效果。

安装后的完整 API 冒烟（`.runtime/desktop-installed-api-final`）通过启动、界面、认证、任务、排队导入、独立解析、事件地点/区间、日历、原 ID 改期、诊断、备份恢复及会话重置。

## 保留与待验

用户已有旧便携实例、此前要求保留的安装实例、数据及专用快捷方式均未关闭、覆盖或删除。原用户实例仍运行，故使用默认数据目录启动新版前，需要用户保存操作并从旧版托盘退出。
